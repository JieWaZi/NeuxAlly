# 插件 v2 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development。用户已批准实施并明确要求两个仓库并行开发；不再重复请求设计确认。

**Goal:** 在公开插件库与 NeuxAlly 之间建立 HTTP 分发契约，统一安装身份，并按当前 CLI 交付原生插件或 Skill/MCP。

**Architecture:** 插件仓库负责原生收录、自有标准包、引用声明、授权桥接及分发清单。NeuxAlly 负责 HTTP 获取、不可变存储、伙伴安装、声明驱动的授权会话、目标派生与会话加载；界面和 allycli 复用安装用例。

**Tech Stack:** Go、SQLite/GORM、React/TypeScript、现有 ACP Runtime、Node 构建脚本、GitHub HTTP API/Release。

**Spec:** [插件 v2 Spec](../specs/2026-10-19-plugin-v2-spec.md) 与 [插件 v2 设计](../specs/2026-10-19-plugin-v2-design.md)。本计划中的最新用户约束覆盖两份讨论文档里的旧 Git 下载和直接原生安装描述。

## Global Constraints

- 公开仓库准确命名 `JieWaZi/NeuAally-Plugins`；本地源仓库和独立实现工作区互不覆盖。
- 两个实现任务并行但分别只修改各自仓库；控制代理维护计划、集成契约、评审及验收。
- 应用运行期间只通过 HTTP/API 查询、下载插件，不依赖 git 可执行文件；安装包不随应用内置。
- 用户安装的是系统插件及伙伴关系；聊天通过 allycli 调用同一安装用例，不写用户 Codex/Claude 全局插件注册表。
- 自有包采用 `.codex-plugin/plugin.json`，可选 `.neuxally/integration.json` 仅表达原生引用和授权扩展，不重复身份或组件定义。
- 原生完整包保留；有目标原生引用则选择它，无引用才使用自有内容；纯引用无实现必须准确失败。
- 原生加载与 Skills/MCP 投影不得重复交付；受限执行不能借整包引入未授权能力。
- 新增插件不能要求增加宿主供应商分支或供应商 UI。插件实现特殊授权协议，宿主管理通用会话和 URL、二维码、验证码动作。
- 凭据不进入 HTTP 公共结果、聊天或日志；沿现有受保护配置、端点和 `ally_` Runtime 身份边界交付。
- 保留第三方作者、许可、源码及补丁来源；根 README 英文与中文对应，开发文档中文。
- 遵守项目 AGENTS 阅读路由；不控制运行中的桌面或页面；不运行未经明确授权的全量检查；保留原检出中的 `docs/discussions/`。

## Review Focus

1. 下载中断、摘要错误、目录穿越：不得发布半包、越界路径或错误来源。
2. 纯引用缺少目标实现、原生解析失败：准确报告，不能偷偷改源或假称已加载。
3. 同一插件并发安装、重试、切换 CLI：关系幂等、版本冻结、当前执行不变。
4. 动态授权多阶段、到期、取消及越范围结果：挑战隔离，秘密与身份约束不丢失。
5. 导入与 README 超长/缺失、未知原生组件：完整原文保留，界面不串版本，不误报兼容。

## 共享接口：HTTP 分发与包根

此接口是软件目录传输结构，不是新的插件清单规范。两个任务必须采用同一字段名，修改前通过控制代理协调。

- `GET https://github.com/JieWaZi/NeuAally-Plugins/releases/latest/download/catalog.json` 是默认目录地址；支持配置 HTTP URL 和本地目录清单，便于镜像、离线及测试。
- JSON 为 `{"schemaVersion":2,"entries":[...]}`，每项字段：`key`、`sourceCommit`（40 位来源提交）、`archiveURL`（不可变 Release 下载 URL）、`archiveSHA256`（64 位摘要）、`packagePath`（如 `neuxally-plugin/github`）、`name`、`version`、`description`、`format`（`codex`）。可选展示字段不能成为第二份运行清单。
- ZIP 解开后就是已核验来源根：包含 `neuxally-plugin/<key>/` 及声明引用的原生目录，`packagePath` 指向逻辑入口。`.neuxally/integration.json` 的 `nativePlugins.<cli>.path` 相对该来源根解析。单包导入以包本身为来源根，不允许越出其快照。
- Release 清单和安装 ZIP 由插件仓库构建命令产生；应用不编译、携带插件 ZIP。每个 ZIP 保留文件内容及执行位。目录搜索只读取目录元数据，不下载所有包。
- 目录返回源身份、可用性与失败状态。已安装内容按摘要固定，不因 latest 清单变化而变化。
- 原生引用键固定 `codex`、`claude`。安装回执区分逻辑版本与目标实际版本、摘要、交付方式及加载阶段。

**Interfaces:** 产生上述 HTTP 清单和 ZIP；提供 GitHub 逻辑入口的两种真实原生引用、自有飞书 Codex 内容、协议 `neuxally-auth/1`。具体桥接消息类型需与 Task 2 对齐，以 Spec 7.3 为基础。

- [ ] README 必须说明：何为系统逻辑插件、使用/安装、三类目录职责、自建 Codex 插件、如何搜集原生包、如何声明引用、HTTP 查询下载、版本固定、许可核对、授权接入步骤；含整体架构 Mermaid 图和授权时序图。不能把计划写成已通过能力。

### Task 2: NeuxAlly 导入、系统安装、原生适配、授权与展示

**工作区：** 应用仓库受管工作树；基线 `81e683e`。只修改应用仓库，不修改本计划和 Task 1 工作区。

**Files:** 重点扩展 `server/internal/plugins/`（package/presentation/storage/catalog 及目标产物）、`server/apis/plugins/`、复用安装用例的 `server/services/`、`server/internal/agentcapability/contract/` 和实际 allycli 调用入口、`server/services/execution/plugins.go`、`server/internal/runtimes/`；前端 `desktop/src/modules/plugin/`；构建 `scripts/plugin-resources.mjs` 不再生成内置安装包；生成 OpenAPI/客户端只能运行项目命令。

**Interfaces:** 消费共享 HTTP 契约；公开 allycli 插件发现/详情/安装/状态操作并绑定当前 Execution/伙伴；声明驱动授权采用 Spec 7.1-7.3，供应商专有流程由插件桥接处理。HTTP 与 CLI 复用真实安装业务方法，不通过 HTTP 包反向依赖实现。
