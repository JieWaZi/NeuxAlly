# 插件资源

## 事实与归属

资源库聚合插件、独立技能和独立连接器。插件资源保存稳定身份与归属；版本保存不可变内容、摘要、原始清单及来源；伙伴安装保存明确版本和启停；共享设置保存唯一修订及加密密钥。伙伴之间不复制账号或配置。

全局资源可先保存在本机，再明确安装到伙伴；伙伴自行导入的资源归该伙伴所有。全局发现与实际安装分别查询。展示名称可以重复，运行时技能身份使用 SKILL.md 的声明名称；同名同内容只投射一份，不同内容拒绝接纳。

包内技能和 MCP 是版本派生组件，不登记为独立安装资源，也没有独立编辑或升级入口。当前模块按新数据库建立目标结构，不包含历史转换或迁移路径。

## 来源与交付

正式解析器位于 `server/internal/plugins`，优先读取 Agent Plugins 1.0.0 清单，同时提供 Claude Skill/MCP 导入适配。未支持的组件产生诊断，非法组件不会进入执行。标准保留变量只在 args、env 与 cwd 中替换；客户端配置绑定位于 `com.ally`，不改写标准字段语义。

本地目录和 ZIP 先完整复制到受管暂存区，预检令牌绑定摘要；摘要使用带长度的路径记录和逐文件摘要，内容不能伪造另一条文件边界。准备时复验相同快照，再写入按完整摘要寻址的内容目录。清单中的 repository 只是作者声明；未核验本地来源使用内容身份，只有明确选择已有插件才更新其版本。随包目录使用经过构建校验的独立目录项身份。

固定插件源通过 [独立 Git 快照](../../plugin-sources/README.md) 维护。构建从来源锁指定的提交生成目录元数据和标准 ZIP，并获取指定目标平台的固定 CLI 资产；Core 运行时只消费本地文件，不同步 Git。目录准备前复验整个 ZIP 摘要，实际安装仍通过统一安全解包和包解析。

飞书办公保留固定官方提交的完整技能目录、相对依赖、许可和 provenance。文档、多维表格、日程和任务是首版主要业务验收路径；第三方作者与包装维护者分别记录于 [第三方声明](../../THIRD_PARTY_NOTICES.md)。

## 安装与变更

点击安装先准备本机资源，必要配置和认证完成后再选择伙伴。准备、授权和数据库安装关系分别处理；取消选择不会产生占位关系，也不会清除已完成的共享认证。批量安装逐伙伴返回结果，重复安装保留原版本与启停。

普通设置更新验证所有保留安装使用的版本。需要同时切换版本时，客户端一次提交目标配置、选定伙伴、目标版本及预期修订。切换目标先复用首次安装的内容、必要组件及认证预检，并持有相应占用。用例在同一事务中校验变更后的完整安装集合，包括未选伙伴和关闭的安装；任何冲突保留全部原状态。

伙伴卸载全局资源只删除该伙伴关系。整体删除先确认实际影响集合，再删除元数据；内容与 PLUGIN_DATA 在数据库引用和活跃执行占用均消失后回收。准备、接纳与回收由同一进程内内容边界协调，回收不穿过受管子目录链接。

## 执行与连续对话

Execution 在接纳时读取同一事务中的资源、版本、安装和配置，复验内容摘要，再投射已有 Skill/Connector 结构。自动按需能力来自伙伴实际启用安装；本轮明确引用通过 pluginIds 单独提交，并只附加本轮选择提示。

STDIO 配置经过 Core 的无协议转换启动模式设置 cwd，保持原始 argv、env 与三个标准流；没有 shell 字符串拼接。MCP 传输依当前智能体探测能力交付，派生服务使用稳定组件授权身份并继续接受现有 MCP 白名单限制。受限入口不会自动取得飞书 CLI 技能和共享 profile 环境；GitHub 仅交付白名单允许的官方 MCP；MCP 白名单本身不构成 shell 沙箱。

消息保存明确选择的插件展示快照，执行保存实际交付插件的版本、配置修订、提供者身份及组件身份，不保存凭据。重试必须满足原版本、配置修订、身份和组件集合，无法恢复时明确失败。原生会话挂载和进程环境继续由 Runtime SDK 管理，提供者身份变化参与环境指纹。

## 共享认证

`internal/plugins/authorization` 统一管理会话、Core 生命周期、取消、工作占用和安全摘要；飞书与 GitHub 适配器只解释各自官方进程。全局和执行装配按提供者保留唯一组件，同一请求按提供者复用身份查询。

固定官方程序通过显式 PATH 进入受管智能体子进程，配置通过 LARKSUITE_CLI_CONFIG_DIR 指向应用私有 provider 目录。授权进程与执行目标均清除继承的官方 CLI 身份、profile、代理及数据目录覆盖，防止外部环境替换共享身份。应用不安装全局程序，不读取其他 CLI profile，也不复制用户 token。

首次配置应用使用官方 App ID 与 stdin 密钥入口；用户授权使用官方设备流程。Core 拥有唯一授权等待、期限与取消，取消后仍保持身份互斥直至设备进程实际退出，并在关闭时等待子进程结束。界面保留原始授权 URL，提供“显示二维码”弹窗和“打开授权页面”两种入口；关闭弹窗不取消等待，等待结束后清理原始链接和验证码，通过统一资源事件恢复状态，没有页面永久轮询。

界面按插件声明请求最小权限，业务返回缺失权限时可明确补充权限标识并重新授权。通过资源库发起的首次配置、退出和身份更换，与使用该身份的活跃执行互斥；占用状态提供关联工作的链接。业务执行收到稳定说明：身份和配置变更回到资源库处理。该协调不宣称隔离同一系统用户自行启动的外部程序；外部撤销和资源权限错误仍可能影响进行中的调用。

GitHub 使用固定 GitHub CLI 2.102.0 源码隔离构建（2.102.0-neuxally.1）的非交互设备流程，不要求用户创建 OAuth 应用。应用私有 `GH_CONFIG_DIR` 使用官方文件凭据，目录 0700、凭据文件 0600；`--insecure-storage` 配合底层 Set/Get/Delete 的 neuxally: 命名空间补丁，避免官方隐式调用及迁移触及机器已有 gh 钥匙串；Core 在任何认证命令前校验隔离构建版本。授权进程清除继承的 GH/GITHUB 覆盖；GitHub profile 与 CLI 目录不交给智能体。退出只移除本应用 profile，不表示撤销服务器授权。

GitHub 权限满足遵循官方包含关系，统一供完成确认、状态、安装、API 缺失权限和执行使用。自动跳过未就绪或无可交付组件的插件时，未被其他实际组件使用的提供者租约在接纳前释放。

GitHub 验证码与原始设备 URL 分开显示，可复制验证码，在手机或网页输入。CLI 不返回官方到期时间，显示 Core 本机 15 分钟等待上限；CLI 自己处理官方设备轮询，前端只消费统一状态事件。

GitHub 插件直接提供官方远程 MCP，CLI 仅由 Core 用于共享认证。实际执行在同一身份占用内验证账号、读取私有 CLI token，将 Bearer 仅注入精确 `https://api.githubcopilot.com/mcp/` 的 streamable HTTP 连接器；其他域、路径、查询或 STDIO 被拒绝。工具组固定为 context、repos、issues、pull_requests、users，清除包内可能覆盖认证和 MCP 选项的请求头。凭据不进入消息、模型指令、共享设置或快照。远程服务由 GitHub 持续部署，不声称实现版本被本地来源锁固定。

## 接口与前端

插件接口在 `server/apis/plugins`，独立技能与连接器通过各自全局 LibraryRouter 和伙伴操作复用同一用例。完整 HTTP 契约由 [OpenAPI](../../server/openapi.json) 生成前端 Client；不手工维护第二份协议声明。

一个资源入口包含三个分类，插件默认为本地插件库与我的插件；URL 保存分类、视图、搜索与分页。伙伴入口显示实际安装和自有准备资源，专业编辑与连接测试继续由原模块负责。服务器事实保存在 TanStack Query，插件和独立资源变化复用现有 Core WebSocket 的提交后事件。
